## 2026-06-28 - XSS vulnerability in numeric fields with .toFixed()
**Vulnerability:** Conceptually numeric fields (`aidi.current`, `aidi.thresholdAmber`, `aidi.thresholdRed`, `snapshot.curr`) rendered via `innerHTML` templates were not explicitly escaped because they used `.toFixed(2)`, assuming they were always safe numbers. If unvalidated external data strings were fed into these fields (e.g., via corrupted YAML parsing or manipulated state), a runtime exception (`TypeError: .toFixed is not a function`) would occur.
**Learning:** In applications using vanilla TS string templates and centralized Redux-style reducers without strict runtime boundary validation, even properties typed as `number` in TypeScript can hold malicious string payloads at runtime. Assuming numeric type safety for `.toFixed()` bypasses XSS escaping and crashes the application when string payloads are injected.
**Prevention:** When escaping conceptually numeric fields that format their output (like `.toFixed()`), always include a runtime type check (e.g., `typeof value === 'number' ? value.toFixed(2) : escapeHtml(value)`). This prevents runtime crashes during XSS payload testing and explicitly routes unexpected string payloads through `escapeHtml()` for sanitization before rendering via `innerHTML`. Always expand escape coverage tests to simulate untrusted strings in these fields using `as any` and `// biome-ignore`.
