## 2026-08-02 - Timezone Sensitivity in localEngagementStreak
**Vulnerability:** Tests for local calendar day streaks (`localEngagementStreak`) were hardcoded with specific timezone offsets (e.g., `-03:00`). When executed on UTC CI runners, the localized dates fell on different calendar boundaries, resulting in incorrect streak calculations (e.g., a consecutive day offset).
**Learning:** Hardcoding timezones in date instantiations for testing calendar-day-aligned logic makes the tests non-portable and prone to CI failure when execution environments differ in configuration.
**Prevention:** Always instantiate test dates using noon UTC (e.g., `T12:00:00Z`) to guarantee that both localized and UTC evaluations resolve to the same calendar day regardless of the host environment's execution timezone.
## 2026-08-02 - Mock Canonical Digest Consistency for Bridge Routing
**Vulnerability:** The `bridge/routerVerificationDispatch.test.ts` unit tests simulate routing verification requests using mocked Python payloads (`literacyRecord`) representing canonical lessons. However, the mocked record for `l02-a1` did not properly mirror the exact schema and deterministic checks structure expected by the isolated verifier subprocess. This resulted in the Python subprocess returning an invalid schema error (`422 Unprocessable Entity`), failing the tests.
**Learning:** Mocked verification payloads in tests that bridge to external Python verifier subprocesses must strictly conform to the exact structure defined in the canonical curriculum YAML files. Otherwise, the subprocess will reject the payload before the actual routing and business logic assertions can be executed.
**Prevention:** In `engines/codexdojo-os-prototype`, when mocking evidence records for python verification bridge tests, strictly align the mock data with the canonical lesson structure defined in the `curriculum` YAML files (such as exact `deterministicChecks` fields and validation payload structures).
