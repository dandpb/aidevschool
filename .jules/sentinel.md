
## 2024-05-18 - [Fix XSS in learner dashboard numerical fields]
**Vulnerability:** XSS vulnerability in numerical fields (AIDI, curr) inside `engines/codexDojo/src/render/learner.ts` due to missing `escapeHtml` wrapping around `.toFixed()` calls. The app dynamically generates HTML by executing templates directly via `innerHTML`, so failing to escape `typeof number` inputs leaves the app vulnerable to malicious scripts that bypass numeric assumptions.
**Learning:** In string-template applications like codexDojo, all dynamic fields—including conceptually numeric fields (e.g. `aidi.current`)—must be escaped using `escapeHtml()` when interpolating into innerHTML templates to prevent XSS vulnerabilities from unvalidated or corrupted external data.
**Prevention:** Always wrap variables passed into innerHTML templates with `escapeHtml()`, especially when calling `.toFixed()` or making numeric assumptions. Use strict type checks (`typeof value === 'number'`) combined with `escapeHtml(value)` to prevent unvalidated strings from crashing the app while ensuring untrusted string payloads are correctly escaped. Maintain robust tests for XSS coverage inside the render layer.
