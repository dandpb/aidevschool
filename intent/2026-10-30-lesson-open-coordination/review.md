# Review and verification

A delayed start reproduced navigation back to a lesson after the learner chose the map. The standalone flow now guards open/review/switch/reset operations synchronously, lets the learner navigate read-only surfaces while those operations finish, publishes the saved progress, and only navigates automatically if the originating screen is still current. Competing actions are announced as unavailable. On uncertain failure the authoritative progress is reread before new actions are enabled; a failed reread blocks mutations with a recovery message. Reset is a separate barrier and blocks internal navigation while active.

Independent review found two additional pre-render races: an old Home action after navigation and an old lesson hint after exit. Screen-origin checks now reject both; independent Chromium checks and component tests verified them. Nine focused component tests cover delayed navigation, competing actions including backup/reset, post-save failure, stale callbacks, reset and failed reread. The full unit suite passed 433 with one skipped; 13 one-worker browser tests passed covering the corridor, backup, checkpoint recovery and interrupted opening; lint and build passed, retaining the existing bundle warning.

This is not a universal write lock: onboarding completion, host/external navigation, refresh/closure, other tabs and clients are outside its guarantee. Independent review found that a partial reset can leave the prior valid state alongside a marker, and the existing boot contract may return that state on reload; reload does not prove reset completed or was rolled back. The reset test simulates failure after the marker in a fake store, not a real browser reload. No formal approval was granted.
