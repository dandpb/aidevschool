# SDLC Quest v1.3 — complete local package

Original campaign, TLC workshop and execution hub, bilingual pt-BR/English. This package keeps the v1.3 game: the changes are packaging, startup, build and test preparation only.

## Start with the local server

Extract the whole ZIP. Inside the `sdlc-quest` folder, with **Node.js 22 or newer** available in the terminal:

```sh
npm start
```

Open **http://127.0.0.1:8080**. Stop it with **Ctrl+C** in the terminal.

**You do not need to run `npm install`.** The server, the build and the rules tests use only Node native modules. There is no remote backend, database, API key or external service required to play. The server listens on this computer only and serves only the game HTML and assets.

The server entry point is `index.html`, which loads `src/`. So, to edit the game, just change the source and reload the page. `sdlc-quest.html` is the self-contained version, generated by the build.

### Per-system launchers

- **macOS:** open `INICIAR-Mac.command`, with Node already installed. If the system blocks the file or cannot find Node, use `npm start` in Terminal inside this folder; no security settings need to change.
- **Windows:** open `INICIAR-Windows.cmd`, with Node available on the PATH.
- **Linux:** run `sh iniciar.sh`, with Node available on the PATH.

The launchers try to open the browser and keep a terminal with the server. They install no dependencies. If the browser does not open automatically, use the address printed in the terminal.

### Another port

```sh
npm start -- --port 8081
```

Open http://127.0.0.1:8081. The command also accepts `--open` to request opening the browser. Changing the port or switching `127.0.0.1` for `localhost` changes the storage origin; always use the same address to keep your progress.

## Playing without Node and without a server

Open **`sdlc-quest.html`** in the browser. It is the complete game in one file: JavaScript, CSS and scenario drawing included, with no CDN or asset downloads. No development dependency is needed for this way of playing.

Browser policies may block opening local files or limit storage. That is why the local server is the preferred option. A temporary preview URL is not a durable place to keep the game.

## Bringing your previous progress

Before leaving the already-open version: **Settings → Download JSON backup**. Then, in the local game: **Settings → Restore backup**, review the preview and confirm.

Importing replaces progress; it does not merge backups. The Harness Lab restores entries, not approvals: your gates need to be run again after reloading or importing. The lab receipts are educational and local.

## Developing and rebuilding

Edit `index.html` and `src/`. To refresh the self-contained HTML:

```sh
npm run build
```

Output: `sdlc-quest.html`. The Node build downloads no packages. The original Python generator (`python3 tools/build.py`) is also preserved; using it is not required.

## Quick tests, without installing dependencies

```sh
npm test
```

Runs the `tests/*.test.cjs` tests, including the campaign rules, the gate engine and the packaging/HTTP tests. The enumerator does not rely on shell glob expansion.

Before editing files or generating new evidence, you can verify the package bytes:

```sh
npm run check:package
```

The `SHA256SUMS.txt` manifest is local and is not a signature. It checks the listed files; it does not attest the absence of extra files. Edits and reruns that change evidence can cause expected divergences.

## Full browser verification — optional

Besides Node, requires **Python 3.10 or newer**. The setup below needs internet to download the testing tools. It is not needed to play, develop or run `npm test`.

```sh
npm run setup:tests
npm run gate
```

The setup creates `.venv/` inside the project, installs `playwright==1.57.0` from `requirements-dev.txt` and downloads Chromium through Playwright. It installs nothing globally and runs no `sudo`. On Linux, the system may also need venv support and the libraries Chromium requires; failures are reported, not ignored.

The runner detects the `.venv/` Python automatically, including on Windows. Activating it is not necessary. The optional variable `QUEST_PYTHON` can point to a full path to another executable; in that case it must have the dependencies installed. The environment is system-specific: recreate the `.venv` after moving the project between computers.

The gate runs local contract → build → rules → desktop/mobile campaign → desktop/mobile TLC workshop → desktop/mobile lab → i18n language journey (desktop). It stops at the first error, timeout or missing dependency. There is no way to skip the tests. Receipts are kept in:

```text
evidence-v1.3/runs/<id>/run.json
```

The existing browser tests use `Playwright.set_content` and explicitly simulated in-memory storage. They must not be confused with native `file://` validation or with testing on a physical device. `CHROMIUM_EXECUTABLE` lets you point to an already installed Chromium; if unset, the helper uses `/usr/bin/chromium` when it exists, or the Playwright browser.

```sh
npm run gate:release
```

This command **does not deploy**. It requires an external authorization that is not configured; after green checks, the expected exit code is **2**. Any verification failure returns **1**. Local approval grants no production authority.

## Skills and harness-toolkit: integration boundary

The campaign and the TLC workshop are educational. The ZIP **does not install or redistribute an official installation** of `tlc-discover`, `tlc-plan`, `tlc-implement` or `the-judge`. The command and prompts from the earlier delivery are in `TLC-GUIDE.md` and in the game; no installation happens at startup.

The hub and `tools/quest-gate.cjs` are the Quest's own implementations. The code of the `dandpb/harness-toolkit` repository **is not part of this package**: its content was not available at the v1.3 delivery, and the real integration remains pending. See `HARNESS-GUIDE.md` and `docs/harness/integration-status.md`.

Nothing here runs remote agents, real PR reviews, merges or deploys. The local server and runner are not a sandbox or an external security barrier.
