# Analytics ownership and effects

Reading map checked against `b9f77774643b94bfd9fafbd756a1b17482c33e45`
(2026-10-04). Follow the linked source for each question. This page describes
existing responsibilities; no module or contract is moved.

## Product telemetry: vocabulary to report

| Responsibility | Source | Boundary |
| --- | --- | --- |
| Closed product vocabularies | [`vocabularies/`](../../engines/shared/teaching-evidence/vocabularies/) | `os.json`, `literacy.json` and `surfaces.json` are the shared JSON authority. |
| OS emission and transport | [`events.ts`](../../engines/codexdojo-os-prototype/src/analytics/events.ts), [`transports.ts`](../../engines/codexdojo-os-prototype/src/analytics/transports.ts) | OS envelope v1; client-side event construction and configured same-origin transport. |
| Standalone LiteracyDojo emission | [`analytics.ts`](../../engines/literacyDojo/src/domain/analytics.ts), [`analyticsBatchSink.ts`](../../engines/literacyDojo/src/adapters/analyticsBatchSink.ts) | Literacy envelope v2; its domain and adapter own emission/batching. [Engine setup](../../engines/literacyDojo/README.md) describes the hosted noop boundary to avoid counting host and standalone paths twice. |
| Programmer-surface emission | [`funnelTelemetry.ts`](../../engines/shared/teaching-evidence/funnelTelemetry.ts) | Shared surfaces envelope v3 for dojoToday, voxelDojo and PixelQuest; distinct from OS/literacy envelopes. |
| Receiving validation and backing | [`dojo-analytics-collector.mjs`](../../learner/gate/netlify-functions/dojo-analytics-collector.mjs) | Validates product batches; POST requires `sec-fetch-site: same-origin`. Default handler selects Blobs when available, otherwise file backing. GET export requires its operator token. These checks do not verify learning evidence. |
| OS function staging | [`build-pilot-bundle.mjs`](../../engines/codexdojo-os-prototype/scripts/build-pilot-bundle.mjs) | Copies canonical function/runtime/package files into engine-local staging and installs function dependencies. Staged collector is a projection, not another source to edit. |
| Input expansion and NDJSON parsing | [`ndjson_input.mjs`](../../learner/gate/analytics/ndjson_input.mjs) | Shared offline input reading with file/line provenance; neither transport nor gate. |
| Drift diagnostics | [`schema_drift_monitor.mjs`](../../learner/gate/analytics/schema_drift_monitor.mjs) | Imports collector validators/tables and checks each line; exits 0 clean, 1 drift, 2 usage/input error. Samples can contain bounded offending-value previews. |
| Aggregate reports | [`aggregate_funnel.mjs`](../../learner/gate/analytics/aggregate_funnel.mjs) | Reads the same NDJSON; suppresses small aggregate cells with k≥5. D2 module mapping reads the [curriculum catalog](../../curriculum/ai-literacy/catalog.yaml) at execution time. Report meaning/options live in the [tool README](../../learner/gate/analytics/README.md). |

The collector's vocabulary blocks are generated by
[`refresh_vocabularies.mjs`](../../learner/gate/analytics/refresh_vocabularies.mjs)
from the shared JSON. `--check` compares present/readable targets without writing;
without it the script can rewrite blocks in the canonical collector and an
existing OS staged copy. Check mode skips unreadable/absent targets, so a passing
check alone does not prove a missing deploy bundle exists.

Product analytics measures experience/engagement, not canonical mastery.
Aggregate suppression does not make raw NDJSON or drift diagnostics into
publishable aggregate reports. Keep real exports outside tracked fixtures;
the examples below use only committed synthetic inputs.

## Other analytics surfaces have different contracts

| Surface | Source | Boundary |
| --- | --- | --- |
| Learner event schemas and validation | [`learner/analytics_events/validate.py`](../../learner/analytics_events/validate.py) | Loads schema JSON versions in its own directory and validates learner event records. These versions are not the product collector's v1/v2/v3 envelopes. Schema migration has its own [script](../../learner/analytics_events/migrate_v2_v3.py), which removes existing destination JSON before writing migrated fixtures. |
| Python SDK instrumentation | [`learner/analytics.py`](../../learner/analytics.py) | Reads root `.env`, initializes an optional PostHog SDK client at import, and exposes identify/capture functions. The [gate CLI](../../learner/gate/__main__.py) and [substrate CLI](../../learner/substrate/__main__.py) import it; calling these CLIs is not just an offline product-funnel read. |

Storage location under `learner/gate/` does not confer learning-gate authority
on the collector or its offline tools. Canonical mastery still follows the
[learner-state interface](../../learner/substrate/interface.md).

## Check sources without activation or regeneration

From the repository root, the following commands check vocabulary bindings and
exercise offline reading with synthetic inputs. Monitor/aggregate write the
explicit output files; the shell creates a new temporary directory. No
collector request, export token, build/staging or Python SDK import is needed.

```sh
node learner/gate/analytics/refresh_vocabularies.mjs --check
analytics_tmp="$(mktemp -d)"
node learner/gate/analytics/schema_drift_monitor.mjs \
  --input learner/gate/tests/fixtures/analytics/synthetic,learner/gate/tests/fixtures/analytics/synthetic-v2,learner/gate/tests/fixtures/analytics/synthetic-v3 \
  --output "$analytics_tmp/drift.json"
node learner/gate/analytics/aggregate_funnel.mjs \
  --input learner/gate/tests/fixtures/analytics/synthetic,learner/gate/tests/fixtures/analytics/synthetic-v2,learner/gate/tests/fixtures/analytics/synthetic-v3 \
  --now 2026-09-18T00:00:00.000Z \
  --output "$analytics_tmp/funnel.json" --markdown "$analytics_tmp/funnel.md"
```
