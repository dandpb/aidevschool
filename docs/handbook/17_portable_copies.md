# Portable copies: find the edit source

## MVP runtime mirrors

The [MVP README](../../engines/aiDevschoolMvp/README.md) owns the tutor's setup
and authority boundary. Its packaged runtime runs without the surrounding
repository. For shared runtime logic, start with the corresponding gate module
and inspect its portable counterpart and the
[existing parity test](../../engines/aiDevschoolMvp/tests/installer/test_runtime_parity.py):

| Shared runtime source | Portable counterpart |
| --- | --- |
| [`learner/gate/core.py`](../../learner/gate/core.py) | [`scripts/_core.py`](../../engines/aiDevschoolMvp/aidevschool/scripts/_core.py) |
| [`learner/gate/engine.py`](../../learner/gate/engine.py) | [`scripts/_engine.py`](../../engines/aiDevschoolMvp/aidevschool/scripts/_engine.py) |
| [`learner/gate/state.py`](../../learner/gate/state.py) | [`scripts/_state.py`](../../engines/aiDevschoolMvp/aidevschool/scripts/_state.py) |
| [`learner/gate/state_transitions.py`](../../learner/gate/state_transitions.py) | [`scripts/_state_transitions.py`](../../engines/aiDevschoolMvp/aidevschool/scripts/_state_transitions.py) |

These are shipped mirrors, not outputs regenerated by the installer. The test
compares parsed top-level functions, classes and uppercase assignments after
dropping docstrings. Imports, comments and formatting are outside that comparison;
portable imports deliberately differ. A passing check proves that comparison,
not identical file bytes or complete installed-runtime behavior. Inspect the
test when a change adds a definition or changes either side.

The engine's [entry scripts and runtime loader](../../engines/aiDevschoolMvp/aidevschool/scripts/_runtime.py),
[curriculum](../../engines/aiDevschoolMvp/aidevschool/curriculum.json), content,
prompts, keys and rubrics remain package-local authoring surfaces. Do not infer
that every script mirrors a gate module. The MVP's `MASTERED` and ledger remain
its own journey; portability does not grant canonical mastery.

[`install.py`](../../engines/aiDevschoolMvp/aidevschool/install.py) verifies the
curriculum and [instrument manifest](../../engines/aiDevschoolMvp/aidevschool/_install_validation.py).
`--check` returns before platform installation. Normal installation copies the
existing skill tree, initializes platform state and configures a recurring review
job. It does not repair divergence between the four source pairs.

## Vendored peers and generated projections

| Mechanism | Edit/navigation source | Existing check and limit |
| --- | --- | --- |
| `harness-eval` vendored peer trees | [.claude](../../.claude/skills/harness-eval/), [.cursor](../../.cursor/skills/harness-eval/), [.windsurf](../../.windsurf/skills/harness-eval/); provenance in [current lock](../../.agents/.skill-lock.json) and [local pins](../../scripts/skill_vendored_pins.json) | [`skill_vendored_guard.py`](../../scripts/skill_vendored_guard.py) checks presence, cross-copy identity, provenance and fixture regressions. No one peer is declared the privileged edit source; a deliberate update must retain the peer contract. |
| Other installed/local skills | Their own SKILL.md and available provenance | The current lock lists only harness-eval. Do not assume unrelated skills in `.agents/`, `.claude/` or another agent tree share this guard's parity contract. |
| Generated vocabulary/function projections | [Analytics ownership map](16_analytics_ownership.md) | JSON → generated vocabulary blocks and canonical function → staged OS copy have explicit scripts. They are a different mechanism from the MVP's shipped mirrors. |

For `source: local`, the vendored guard uses the deliberate pin, rather than
requiring the current tree to match the lock's historical catalog contentHash.
Its tree hash excludes dotfiles/dotdirs and `__pycache__`; cross-copy identity
is a separate comparison. `--update-pins` rewrites the pin file: it is not a
repair command to run merely because a check fails. The lock/pins and guard
are the authority for this mechanism, not the backup lock file or this map.

## Validation without installation or updates

From the repository root:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 engines/aiDevschoolMvp/aidevschool/install.py --check
PYTHONDONTWRITEBYTECODE=1 python3 scripts/skill_vendored_guard.py
```

The first validates curriculum/instruments without installing or synchronizing
runtime mirrors. The second checks vendored integrity/provenance and runs its
checker against a temporary fixture copy; it does not update pins or peer trees.
Neither command establishes parity of all MVP behavior. The AST contract remains
in the linked test; a future runtime change needs its focused verification and
independent review, including installed execution when imports/packaging change.
