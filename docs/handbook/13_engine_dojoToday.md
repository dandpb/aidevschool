# Engine — dojoToday

**Path:** `engines/dojoToday/` · **Type:** runnable app (read-only surface) · **Audience:**
programmers on the DevSchool track.

## Role in the ecosystem

dojoToday is the **"lesson for today"** surface for programmers, in a
Duolingo-style voxel presentation: the current sequence, the reviews due
(scheduled by FSRS from the gates), the streak, and the active unit. It is the
glue between the shared substrate scheduler and the voxel teaching games.

It consumes the shared learner substrate through a **generated read model**:
`src/data/today.ts` is produced by the substrate adapter
(`learner/substrate/adapters/dojotoday.py`, which calls
`learner.substrate.scheduling`) and is regenerated by the prebuild hook
(`python3 -m learner.substrate`). The file is marked DO NOT EDIT.

## Status authority

- The [learner substrate](08_learner_substrate.md) owns the canonical state,
  the FSRS scheduling, and the gate results that dojoToday renders.
- The [engine README](../../engines/dojoToday/README.md) owns implementation
  details and the current commands.
- This handbook page owns only the cross-engine role and boundaries; it does
  not copy operational status.

## Boundaries

- dojoToday is **read-only**: it never schedules, never evaluates, and never
  marks `mastered`. Producer ≠ verifier.
- `src/data/today.ts` is generated; never edit it by hand — change the
  canonical YAML under `learner/` and regenerate via the substrate.
- No UI framework: vanilla DOM + TypeScript + Vite (same pattern as codexDojo).
- The optional Sócrates assistant is deterministic by default and never
  overrides the gate.

## Run and validate

Use the [engine README](../../engines/dojoToday/README.md) for prerequisites.
The base technical suite is:

```bash
cd engines/dojoToday
npm run lint        # biome check src tools
npm run selfcheck   # python3 tools/selfcheck.py (substrate adapter self-check)
npm run build       # prebuild regenerates the read model, then tsc + vite build
```
